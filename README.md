# 市政道路施工封路方案协调与审批平台

源提示词编号：11。支持分段封路范围、施工阶段、绕行路线、车道收窄和临时设施的同一地图协作；检查相邻工程、救护通道、公交覆盖和绕行时延冲突；提供图层开关、路线绘制、阶段时间轴、条件会签、版本比较和公开通告包导出。

## 技术栈

Vue 3、Arco Design Vue、Pinia、Vue Router、Apollo Client、GraphQL、MapLibre GL、Vite、TypeScript。

## 运行

```bash
npm install
npm run dev
```

开发地址：http://localhost:62054

```bash
npm run build       # 类型检查 + 生产构建
npm run test:collab # 协作引擎规则测试（13 项单元规则 + 四单位完整剧本）
```

## 可恢复的版本协作模型

四家单位（建设 / 交通 / 公交 / 应急）共用一份封路方案。以 localStorage 模拟共享文档库，
**同一浏览器开多个标签页（可在右上角切换单位身份）即为多单位并发场景**，跨标签页实时同步。

- **提交号 + 基准版本**：每次保存携带 `commitId` 与 `baseVersion`（当前已发布版本号）。
- **同号只留首次结果**：提交号在服务端幂等登记；重复/重试返回第一次的结论，不重复落库、不重复推进版本。
- **同基准并发先到先得**：版本号线性推进，基准落后的后到提交不生效，其完整内容保留为「冲突草稿」。
- **冲突合并工作台**（多单位会签页）：可预览后到内容与先提交版本的字段差异，选择
  「采纳（以当前版本为新基准重放）」或「放弃（留痕不合并）」；处理结果与合并提交号全部进入版本历史。
- **意见级联**：
  - 阶段**起止时间或封路路线**变化后，依附旧版本的「待处理」意见立即标记**失效重算**，
    重新挂接到新版本并交原单位重新确认；只改车道/名称等非锚点字段不触发。
  - 「已接受」意见在接受时**冻结当时依据**（版本、提交号、起止、车道、路线快照），
    关联阶段再变时自动转「待复核」，冻结依据保留供对照，复核通过时按当前版本重新冻结。
- **通告导出闸门**：存在待处理冲突草稿、未提交本地草稿、未回放的离线发件箱（含其他单位）或处于离线时，
  公开通告不可导出；导出本身也是一次带提交号的版本提交，通告文本锁定生效版本号。
- **可恢复草稿**：阶段编辑先进入本单位本地缓冲，保存时才提交；断网期间的提交进入 FIFO 发件箱，
  刷新、断网、重开浏览器后缓冲与发件箱均不丢失，联网后按序回放——
  同单位连续提交自动顺移基准，跨单位抢跑则如实保留为冲突草稿。

规则核心位于 `src/collab/engine.ts`（纯函数，可脱离界面测试），
Pinia 侧的缓冲 / 发件箱 / 合并动作为 `src/store/scheme.ts`。
